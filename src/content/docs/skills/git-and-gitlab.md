Git 解决的是一个非常具体的问题：<b>当一份文件被改了三十次、还被三个人同时改过，你怎么知道哪一版是对的、以及怎么退回去。</b>

<b>先记住这一条就够</b>：本地敲 `git status`，收工前敲 `git push`。其余命令可以边用边查。

## 为什么现在就该学

| 场景 | 具体会发生什么 |
| --- | --- |
| <b>课程大作业</b> | 三个人改同一份代码，靠微信传压缩包，最后谁的版本都不完整。用 Git 后，合并是一次操作，冲突有明确提示。 |
| <b>实验与程序课</b> | 调通了一版，继续改之后又崩了，回不到刚才那版——这是没有版本控制的典型损失。 |
| <b>进实验室</b> | 师兄师姐给你的代码大概率在 Git 仓库里。不会 `clone`，你连第一步都迈不出去。 |
| <b>写论文/毕设</b> | 论文、代码、数据版本对不上，是复现失败的最常见原因。 |
| <b>实习</b> | 几乎每份研发实习都默认你会用 Git，面试也会问。 |

> 它不只是程序员的工具
>
> Git 管的是<b>文本文件的历史</b>。实验数据处理的脚本、LaTeX 论文、甚至配置文件的改动记录，都可以用它。只要内容是文本、并且你会反复修改，它就适用。

## 马上能做的

- [ ] 装好 Git（下载慢的话先在<a href="https://mirrors.tuna.tsinghua.edu.cn/">清华镜像站</a>里找找有没有对应的镜像），配置好用户名和学校邮箱。

- [ ] 在<a href="https://git.tsinghua.edu.cn/">校内 GitLab</a>上建一个<b>私有</b>仓库，把一门课的代码传上去，完整走一遍 clone → 改 → add → commit → push。

- [ ] 给这个仓库加一个 <code>.gitignore</code>，把数据文件、编译产物、含密码的配置文件排除掉。

- [ ] 故意建一个分支、改一行、再合并回来，感受一次分支是什么。

- [ ] 把「动手前先 <code>git status</code>」变成肌肉记忆。

## 最小可用路径

### 第 1 步：理解三个区域，一切就都清楚了

Git 的所有命令，本质都是在<b>在这三个区域之间搬东西</b>：

| 区域 | 是什么 | 相关命令 |
| --- | --- | --- |
| <b>工作区</b> | 你正在编辑的文件 | 你直接用编辑器改 |
| <b>暂存区</b> | 你挑出来“这次要提交”的改动 | `git add` |
| <b>版本库</b> | 已经存成快照的历史 | `git commit` |

远端仓库（校内 GitLab 或 GitHub）是第四个位置：`git push` 送上去，`git pull` 拉下来。

### 第 2 步：这十条命令够你用一整个学期

| 命令 | 作用 | 什么时候敲 |
| --- | --- | --- |
| `git clone <地址>` | 把远端仓库整个拷到本地 | 第一次拿到项目 |
| `git status` | 看现在有哪些改动、在哪个分支 | <b>每次操作前</b>，最该养成的习惯 |
| `git add <文件>` | 把改动放进暂存区 | 提交之前 |
| `git commit -m "说明"` | 生成一个版本快照 | 做完一件小事就提交，不要攒一天 |
| `git log --oneline` | 看历史提交列表 | 想知道“什么时候改坏的” |
| `git diff` | 看具体改了哪几行 | commit 前自查 |
| `git pull` | 把别人的改动拉下来 | <b>每天开工第一件事</b> |
| `git push` | 把本地提交传到远端 | <b>每天收工最后一件事</b> |
| `git switch -c <分支名>` | 新建并切到一个分支 | 做实验性改动、多人分工时 |
| `git merge <分支名>` | 把分支合并回当前分支 | 一个功能做完 |

> 提交信息写给自己看
>
> 半年后回来找“哪次改动弄坏了程序”的人是你自己。`fix: 修正数据读取时的编码问题` 比 `update` 有用一百倍。

### 第 3 步：明确哪些东西不该进仓库

下面这些一旦提交，清理起来很麻烦（历史里会一直留着）：

-   <b>数据文件、模型权重、压缩包</b>：仓库是给文本用的，大文件会让 clone 变得极慢。
-   <b>密码、访问令牌、密钥文件</b>：等同把家门钥匙贴在门上。
-   <b>编译产物、缓存、依赖目录</b>：能重新生成的都不要提交。
-   <b>别人的代码、未公开的数据</b>：先确认你有没有权利放进去。

把它们写进 `.gitignore` 是<b>建仓库后的第一件事</b>，不是“以后再整理”。

### 第 4 步：遇到冲突不要慌

冲突的本质是“同一行被两边改成了不同内容”，Git 不敢替你决定。处理顺序：

1.  打开被标记的文件，找到 `<<<<<<<` 和 `>>>>>>>` 之间的两段内容。
2.  决定保留哪一段（或者两段都改写成第三种写法）。
3.  删掉那些标记符号，保存。
4.  `git add` 这个文件，然后 `git commit`。

> 冲突不是错误
>
> 冲突说明 Git 正常工作了。<b>真正危险的是你为了省事直接 </b> <b><code>git push -f</code></b> <b> 覆盖别人的提交</b>——那会真的把别人的工作删掉。共享分支上永远不要这么做。

## 校内 GitLab 与 GitHub 的分工

两个都是 Git 平台，用法基本一样，区别在于<b>给谁看、放在哪</b>：

|  | 校内 GitLab | GitHub |
| --- | --- | --- |
| <b>主要用途</b> | 课程项目、实验室内部代码、需要私有仓库的东西 | 开源项目、个人作品集、实习与申请时给别人看 |
| <b>账号体系</b> | 校内账号体系（登录方式以站点说明为准） | 自建账号 |
| <b>访问</b> | 校园网内直连；不在校内时可能需要通过学校 VPN | 从境内访问的稳定性视网络情况而定 |
| <b>适合放</b> | 课程作业、组内代码、不想公开的东西 | 能公开的技术积累、简历上想展示的项目 |

<b>建议的做法</b>：重要的东西<b>两边都放一份</b>，或者至少在校内平台上有一份完整的。把唯一的一份代码放在一个你无法保证随时访问的地方，是没必要的风险。

> 校内系统的具体细节以官方为准
>
> [校内 GitLab](https://git.tsinghua.edu.cn/)的登录方式、是否需要校园网或 VPN、单人可建仓库数量、单仓库容量、是否提供 CI 等，均由学校信息化部门规定并可能调整。<b>本站不写这些具体规则</b>，请在站点首页的说明里确认，或从[信息门户](https://info.tsinghua.edu.cn/)进入后查看相关文档。

> 校外访问的通用做法
>
> 不在校园网时访问校内服务，通常需要通过学校的 VPN 入口（见[校内常用链接](/guides/links/)里的说明）。<b>不要使用来路不明的代理工具</b>，也不要把账号交给第三方服务。

## 常见坑

> 警告
>
> -   <b>只在本地 commit，从不 push。</b> commit 只是存在你自己电脑上，硬盘坏了就全没了。push 才算备份。
> -   <b>把密钥或令牌提交进仓库。</b> 即使之后删掉文件，历史里仍然留着。发现后要<b>立刻在平台上作废那个密钥</b>，再换一个新的。
> -   <b>一个 commit 塞进一天的工作。</b> 出问题时你无法只回退其中一部分。
> -   <b>提交信息写 “update”、“1”。</b> 等于没写。
> -   <b>所有人都在 main 上直接改。</b> 小作业还能撑住，人一多必然互相覆盖。
> -   <b>把数据文件、虚拟环境目录一起提交。</b> clone 时间从几秒变成几十分钟。
> -   <b>用 Git 管 Word/Excel 文件。</b> 二进制文件无法看差异，每次改动都是一整个新版本，越用越臃肿。
> -   <b>以为“进过仓库”就等于“永久保存”。</b> 平台可能变更、账号可能失效，重要的东西请另外留一份到[校内云盘](https://cloud.tsinghua.edu.cn/)或本地。

## 延伸阅读

-   [Pro Git 中文版](https://git-scm.com/book/zh/v2) —— Git 的官方书，免费。<b>当字典用</b>：遇到“撤销提交”“找回删掉的分支”这类问题再翻对应章节，不要从头读。
-   [Learn Git Branching](https://learngitbranching.js.org/) —— 在浏览器里用可视化的方式练分支和合并，不用装任何东西。分支概念绕不过来时，玩半小时比看十篇文章有用。
-   [Missing Semester 中文版](https://missing-semester-cn.github.io/) —— 把终端、Git、脚本串成一节课讲，适合想一次补齐基础工具的人。
-   [计算机系学生科协技能引导文档](https://docs.net9.org/) —— 里面有一篇更偏操作细节的 Git 入门，装软件、配置、常见操作都可以对照着看。
