工具本身不产生价值。<b>但不会用工具，会让你在本来十分钟的事情上花掉一晚上</b>：小组作业靠微信互传文件、实验报告的公式靠截图、参考文献靠手打编号。

这个板块只解决一个问题：<b>在你真正需要某项技能之前，用最短的时间把它学到“够用”。</b>

## 先给结论

如果只记一句话：<b>不要为了学工具而学工具，等它挡在你面前再学。</b>

但有六件事挡在面前的概率极高，而<b>提前一两周准备的成本，比临时抱佛脚低得多</b>：

| 技能 | 你第一次真的会用到它，通常是…… |
| --- | --- |
| [版本管理与校内 GitLab](/skills/git-and-gitlab/) | 小组大作业要合并代码；进实验室后要跑师兄师姐留下的代码 |
| [LaTeX 与校内 Overleaf](/skills/latex-and-overleaf/) | 第一份实验报告要求公式排版；课程论文有格式要求 |
| [Markdown 与笔记系统](/skills/markdown-and-notes/) | 开学两个月，笔记散在六个地方，期末哪个都搜不到 |
| [命令行与 Linux 基础](/skills/command-line/) | 要连实验室的服务器；装环境的教程从头到尾都是终端命令 |
| [文献管理与引用](/skills/reference-manager/) | 写第一篇带参考文献的论文或综述 |
| [数据处理与画图](/skills/data-and-charts/) | 物理实验要画图；大作业要处理一份几千行的数据 |

## 这个板块怎么用

<b>三种读法，按你的处境挑一种：</b>

1.  <b>救火式</b>（最常见）。现在就有个作业卡住了，直接跳到对应那一篇，只看「最小可用路径」那一节。
2.  <b>开学前扫一遍</b>。每篇花十分钟读「为什么该学」和「常见坑」，知道有这些东西存在。真需要时，你会知道该回来看哪一篇。
3.  <b>按一条主线学</b>。如果你打算进实验室，推荐的顺序是[命令行](/skills/command-line/) → [Git](/skills/git-and-gitlab/) → [文献管理](/skills/reference-manager/) → [数据处理与画图](/skills/data-and-charts/)。这条线上每一环都是下一环的前置。

> 别从第一篇读到最后一篇
>
> 工具技能的遗忘率极高，<b>没有使用场景的知识两周就忘干净</b>。所以本板块每篇都在回答“它到底在哪用得上”，而不是把软件说明书抄一遍。

## 每篇大致是这个结构

小标题会按主题略作调整，但顺序基本一致。熟悉之后，你可以只读你要的那一段：

1.  <b>先给结论</b> —— 这一篇最重要的判断，一段话说完。
2.  <b>为什么现在就该学</b> —— 具体到课程名、科研场景、实习场景，而不是“很有用”。
3.  <b>马上能做的</b> —— 几条当天就能完成、且<b>做完确实有产出</b>的动作。
4.  <b>最小可用路径</b> —— 按步骤走一遍，能覆盖日常需求的最小集合。
5.  <b>校内资源与外部文档</b> —— 校内有哪些入口，剩下的细节去哪份官方文档查。
6.  <b>常见坑</b> —— 别人踩过的，你不用再踩一次。
7.  <b>延伸阅读</b> —— 两到四份真正值得读的外部文档，并说明各自解决什么问题。

## 和外部文档的分工

本站是经验帖，不是教程。这个分工很重要，弄错了会浪费你的时间：

| 你想知道 | 该去哪 |
| --- | --- |
| 这东西<b>值不值得学</b>、什么时候学、学完用在哪 | 这个板块 |
| 校内有没有现成的入口和资源 | 这个板块 + [校内常用链接](/guides/links/) |
| 出了错<b>大概率是什么原因</b> | 这个板块的「常见坑」 |
| 某个命令的<b>完整参数</b>、某个函数的<b>全部选项</b> | 工具的官方文档（每篇末尾都给了入口） |
| 语法细节、边角情况、版本差异 | 官方文档或[学习资料库](/guides/links/)里的学生文档 |

> 为什么不直接写教程
>
> 因为教程会过期，而判断方法不会。命令的参数在官方文档里永远是最新的，我们抄一遍只会给你一份<b>可能已经过时的二手资料</b>。

> 如果你做的是宣传工作
>
> 上面六项偏“课程与科研”，做社工宣传岗要用的<b>排版、平面设计、活动摄影、照片后期、短视频</b>另开了一个板块： 见[宣传与传播](/publicity/)。两者不重叠——工具是通用的，宣传那几篇讲的是“做出来给人看”这件事。

## 学工具的三条原则

1.  <b>用得上再学，边做边学。</b> 看十个小时的视频，不如拿自己的真实任务练一小时。
2.  <b>先跑通，再讲究。</b> 第一次用 Git，只要能把代码推上去就够了；合并冲突、rebase 这些等你真的遇到再说。
3.  <b>留一份能复现的记录。</b> 你解决报错的过程值得记下来（命令、报错原文、最后怎么解决的）。半年后你还会遇到同一个错。

## 马上能做的

- [ ] 打开<a href="/guides/links/">校内常用链接</a>，把其中三个入口存成浏览器书签。

- [ ] 从上面六篇里挑一篇，只读「为什么现在就该学」和「常见坑」两节，十分钟。

- [ ] 挑一件你这周本来就要做的作业，用这个板块里的某项技能做一遍（哪怕只用了十分之一）。

- [ ] 建一个自己的「踩坑记录」文件，今天往里写第一条报错和它的解法。

- [ ] 如果某项技能你已经会了，把你在校内实际怎么用的经验补进对应那一页。

## 常见坑

> 警告
>
> -   <b>收藏了教程就等于学会了。</b> 收藏夹里的教程不会自己进你的脑子。学工具必须在真实任务里过一遍手。
> -   <b>同时开三个工具坑。</b> 一学期同时学 Git、LaTeX、Python，结果三个都停在“装好了”。
> -   <b>把工具当成目的。</b> 会用 LaTeX 不说明你的报告写得好；会写 Python 不说明你的数据结论对。工具只负责让你<b>少花时间在机械劳动上</b>。
> -   <b>拿工具做它不擅长的事。</b> 用 Markdown 排需要精确格式的正式文件、用 Excel 管理上万行要反复处理的数据，都是自找麻烦。每篇的「常见坑」都会点到这些边界。
> -   <b>在在线平台上放不该放的东西。</b> 未公开的数据、涉密内容、他人的个人信息，不要上传到任何在线服务。

> 本板块不写什么
>
> -   <b>不写具体的账号与登录流程</b>，也不贴系统截图。这类内容变化最快，写在这里只会误导人。
> -   <b>不写任何绕过权限、绕过认证的做法。</b> 遇到权限问题，正确做法是找管理员，不是找捷径。
> -   <b>不推荐付费课程和付费工具。</b> 有免费方案就先讲免费方案；商业软件请通过学校授权或官方渠道获取。

## 这一块欢迎你补

技能类内容有一个特点：<b>方法稳定，但校内入口会变</b>。所以下面这些位置我们留给了知道实情的人：

-   校内系统（GitLab、Overleaf、云盘、镜像站）的实际使用体验、容量和权限限制。
-   你在某门课上真正用到某项技能的<b>具体场景</b>——这个比任何通用建议都有价值。
-   你踩过的、本文没写的坑。

写法和流程见[怎么贡献一篇经验帖](/contribute/)。<b>涉及校内系统流程的内容请注明适用年份</b>，并说明哪些地方是“以官方通知为准”。
