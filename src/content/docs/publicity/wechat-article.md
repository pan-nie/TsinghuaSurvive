推送是校园宣传里<b>最常用、也最容易做丑</b>的形式。丑的原因通常不是“审美不行”，而是没人告诉过你：字号该多大、段落该多长、什么时候该用图、什么时候该收手。

> 先给结论
>
> 推文排版的本质不是“设计”，是<b>降低阅读成本</b>。
>
> 读者在手机上给你的时间大约是 3 秒。你只需要做到两件事：<b>信息层级一眼能分出来</b>（谁是标题、谁是重点、谁是图注），以及<b>手机端真的看过一遍</b>。 其余的（模板好不好看、有没有 SVG 动效）都是加分项，不是及格线。

## 一、工具分工：四个工具各管一段

先把工具用对，能省掉一半返工：

| 工具 | 管什么 | 什么时候用它 |
| --- | --- | --- |
| <b>秀米</b> | 图文排版、SVG 效果、导出到公众号 | 默认选择。功能最全，模板最多，能直接绑定公众号导出 |
| <b>可画</b> | 位图：海报、长图、封面、无缝图 | 需要“整块图片”时用。做好导出 PNG，再整张放进推送 |
| <b>PS 一类位图软件</b> | 抠图、修图、合成 | <b>按需学</b>，不要系统学。遇到具体需求再查具体操作 |
| <b>公众号后台</b> | 发布与最后的细节微调 | 只做发布。正文排版不要在这里改，改一处会带乱一串 |

> 关于“用 AI 直接生成推送”
>
> AI 能生成推送的排版代码，也能生成模板，但<b>生成完必须有人调</b>：字号、间距、边距、图片比例在手机上的实际效果，只能靠看。把 AI 的产出当“初稿的初稿”，不要当成品。

## 二、秀米：为什么“表格”是排版的基本单位

秀米的排版逻辑和 Word 完全不同，理解这一点，很多“怎么都对不齐”的问题会自己消失。

<b>秀米里的一切排版都基于表格（组件）</b>。一个组件的行为有三条：

1.  <b>宽度手动调整</b>——你设多少就是多少；
2.  <b>高度自适应</b>——内容多了它会变高，你不需要（也常常不能）直接设死高度；
3.  <b>位置手动调整</b>——可以左右移动、可以重叠。

由此推出两条实用结论：

-   <b>删掉上面一块，下面的内容会自动往上补。</b> 所以调整顺序不用复制粘贴，删了重排更快。
-   <b>调整高度靠“内容”，不靠“拉框”</b>：常用的做法是在文本框里<b>前插空行或后插空行</b>，或者用组件定位（外边距/内边距）把它顶下去。

### 六个可以调的东西

进入<b>布局模式</b>后（右上角），你实际能控制的只有这六个：

| 元素 | 作用 | 常见误用 |
| --- | --- | --- |
| <b>宽度</b> | 决定一行能放多少字 | 设得过宽 → 手机上两侧被裁 |
| <b>高度</b> | 由内容撑开，靠空行/定位调整 | 想把高度“拉”到某个数值 |
| <b>定位</b> | 左右偏移、上下错位 | 靠定位做复杂布局，换个机型就散 |
| <b>缩放</b> | 整体放大缩小 | 用它代替改字号 |
| <b>边距</b>（内/外） | 控制留白，<b>两侧边距由内外边距共同决定</b> | 两边都设很大，正文被挤成一条 |
| <b>次序</b> | 重叠图案的上下层 | 图压住了字，找不到谁在上面 |

> 六大元素里最值得花时间的是“边距”
>
> 手机屏幕窄，<b>留白是排版最便宜的奢侈品</b>。两侧内边距 + 外边距之和一般控制在 <b>15–25</b> 之间——具体值看你的模板，但“加起来别超过 25”是很稳的经验。

## 三、从套模板到自由修改：三层

新手最容易卡在“模板好看但不合我的内容”。按这三层递进，会顺手很多：

| 层级 | 你能改什么 | 难度 |
| --- | --- | --- |
| <b>改模板</b> | 只换文字和图片 | 最省事，但想改结构就会崩 |
| <b>套组件</b> | 把模板拆开，用里面的组件重新拼 | 中等：排版方式和位置可调 |
| <b>改组件</b> | 直接调字号、间距、SVG 参数 | 最好改，也最自由 |

三条实践建议：

1.  <b>找“视觉风格和预期效果一致”的模板</b>，而不是找“最花哨的”。风格对一个，你只需要改内容；风格不对，你怎么调都别扭。
2.  <b>善用收藏。</b> 遇到一个顺手的标题组件、一个好看的分割线，收藏起来，下次直接调。
3.  <b>大胆修改。</b> 模板是起点不是终点，尤其是<b>视觉风格（配色、字体、整体气质）不好改</b>，<b>排版方式（位置、SVG 参数）可以改</b>——先判断你面对的是哪一种。

## 四、文字排版：一套可以直接照抄的规范

<b>基本原则只有一句：符合大众阅读习惯、简洁易读、格式统一。</b>

### 字号

| 用途 | 字号 | 说明 |
| --- | --- | --- |
| 主标题 | <b>&gt; 24</b> | 一眼看到的那个 |
| 章节标题 | <b>16–24</b> | 和小标题配合 |
| 正文 | <b>15–16</b> | 低于 15 在手机上会很费眼 |
| 结尾落款 | <b>12–14</b> |  |
| 图注 | <b>12</b> |  |

### 颜色

-   正文用<b>偏灰的黑色</b>，不要纯黑（纯黑在手机上偏硬）。
-   重点内容可以单独用一种颜色标出来——<b>只允许一种</b>。
-   图注和落款用灰色 <b>#B2B2B2</b>。

### 字体

-   <b>用默认字体就好。</b> 手机端能显示的自定义字体非常有限，你选的字体在读者那里大概率不生效。
-   <b>无衬线体比衬线体更易读</b>（手机上这个差别很明显）。

### 常用格式（照抄即可）

| 项目 | 建议值 |
| --- | --- |
| 行间距 | <b>2.0</b> |
| 字间距 | <b>0–1</b> |
| 两侧边距 | 内 + 外 = <b>15–25</b> |
| 段落间距 | <b>0</b>（靠空行分段，不靠段间距） |
| 对齐 | 正文<b>左对齐或两端对齐</b>，<b>全篇一致</b>，<b>无首行缩进</b>；不要居中 |

### 留白的规矩

-   <b>小标题</b>：与上文空<b>两行</b>，与下文空<b>一行</b>。
-   <b>段与段</b>：空<b>一行</b>。
-   <b>上下文与配图之间</b>：空<b>一行</b>。
-   <b>段落长度</b>：不要超过手机一屏字数的一半。超过了就拆段。

### 强调

-   小标题：<b>增大字号</b>。
-   重点：<b>加粗 + 变色（一种主色调）</b>。
-   <b>中文排版少用下划线和斜体</b>——下划线像链接，斜体在中文里几乎不起区分作用。

> 电脑上好看 ≠ 手机上好看
>
> <b>每次改完，一定用手机预览。</b> 电脑上的宽度是手机的两倍多，字号、边距、图片比例、组件对齐在两者上完全不是一回事。绝大多数“发出去才发现崩了”都是这一步省掉了。

## 五、SVG：动效值得做吗

<b>SVG 是可缩放矢量图形</b>，一种描述二维图形的语言。在微信推文里，它可以实现<b>交互与动态效果</b>（点击展开、滑动、渐变），这些是普通图片做不到的。

两条实现路径：

| 路线 | 优点 | 代价 |
| --- | --- | --- |
| <b>用编辑器里的 SVG 模板/组件</b> | 封装的包，简单易上手 | 灵活性有限，效果受限 |
| <b>直接编辑源代码</b> | 能实现复杂效果 | 极为繁琐，改一次要很久 |

实践建议：

-   <b>先看有没有现成的。</b> 去 [e2.cool](https://e2.cool/) 这类站找你想要的效果，多数常见交互都有封装好的代码。
-   <b>SVG 要多试。</b> 只有真的做过几个，你才知道哪些组件能用、哪些组合会互相打架。
-   <b>为效果而效果是不值得的。</b> 一条通知类推送加三个动效，只会让人找不到信息。

## 六、长图：最稳的兜底方案

当排版需求超出了图文编辑器能表达的范围（复杂版式、整块的设计感、非要严丝合缝的图形），<b>别硬在编辑器里拼</b>：

1.  在可画里把这一整块做成一整张图（PNG 导出）；
2.  把图放进推送。

好处是<b>格式绝对一致</b>——你在哪里看都一样，不依赖机型和编辑器解析。代价是<b>没有动态效果</b>，且手机端文字被“烧”进图片里，<b>无法被搜索、无法被复制、也无法被屏幕阅读器读出</b>。

> 什么时候该用长图
>
> 内容以<b>视觉为主</b>（海报式、图鉴式、数据可视化）时用长图；内容以<b>文字为主</b>（通知、攻略、名单）时用图文排版。<b>纯文字做成图片是失败的排版</b>，读者想复制一个时间地点都做不到。

## 七、深色模式

微信有深色模式，它会<b>自动反色</b>部分元素。三个高频崩法：

-   <b>透明背景的 PNG</b>：浅色底图上会变成一坨黑边或糊掉；
-   <b>深色文字配浅色底</b>：反色后对比度消失；
-   <b>纯白/纯黑的分割线</b>：反色后突兀。

<b>检查方法</b>：手机预览时切一次深色模式，重点看图注、分割线、按钮和图里的文字。

## 八、出稿前自检

- [ ] <b>手机预览过一遍</b>（不是只在电脑上看）

- [ ] <b>深色模式看一遍</b>

- [ ] 字号对得上（正文 ≥ 15，主标题 &gt; 24）

- [ ] 强调色只有<b>一种</b>

- [ ] 每个段落之间都有空行，没有一段超过一屏的一半

- [ ] 首行没有缩进，对齐方式全篇一致

- [ ] 图片能看清、没有被裁掉主体，每张图都有说明

- [ ] 提到的时间、地点、人名、单位逐字核过（<b>宣传出错最贵的就是这一项</b>）

- [ ] 链接、二维码点一遍

- [ ] 通读一遍，删掉所有可以删的字

## 九、常见坑

> 警告
>
> -   <b>只看电脑预览。</b> 排版的头号杀手，没有之一。
> -   <b>字号偏小。</b> 电脑上 14 看着正常，手机上就是“要眯眼”。
> -   <b>强调色用了三种以上。</b> 全都强调等于没有强调。
> -   <b>一段顶到底。</b> 手机一屏塞满文字，读者直接划走。
> -   <b>模板换图后没重排。</b> 模板的图有固定比例，换了图之后对齐全乱。
> -   <b>所有信息挤在第一屏。</b> 标题、时间、地点、报名方式、二维码一起上，结果哪个都不突出。
> -   <b>改完在后台又动了一次格式。</b> 公众号后台的编辑器会“顺手”改样式，正文排版尽量只在一个工具里完成。
> -   <b>把纯文字做成图片。</b> 见上一节。

> 这一篇的时效说明
>
> 排版规范是<b>通用经验</b>，不随年份变化，所以不标注核对日期。 但工具本身的按钮位置、免费额度、导出规则会变——以软件里的当前说明为准。
